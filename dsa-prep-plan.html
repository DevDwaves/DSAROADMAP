Phase 0 · Weeks 1–2
Ground Zero — Language & Math Foundations
Prerequisite · No prior DSA needed · 2 weeks
Professor's Note: Most students skip this and then wonder why their code is slow or wrong. You must understand Big-O, how memory works, and how your chosen language handles data before touching a single LeetCode problem.
Big-O Notation & Complexity
Foundational
Master before anything else
  • Time complexity: O(1), O(log n), O(n), O(n log n), O(n²)
  • Space complexity and auxiliary space
  • Amortized analysis (why ArrayList push is O(1) amortized)
  • Best / Average / Worst case distinctions
  • Recurrence relations (T(n) = 2T(n/2) + n → O(n log n))
Language Mastery
Foundational
Python / Java / C++ — pick ONE and go deep
  • Built-in data structures (list, dict, set, deque, heapq)
  • String manipulation and immutability
  • Pass-by-value vs pass-by-reference
  • Lambda, list comprehension, generators (Python)
  • STL (C++) / Collections framework (Java)
Math for DSA
Foundational
Essential number theory & combinatorics
  • Modular arithmetic (a + b) % MOD
  • GCD / LCM (Euclidean algorithm)
  • Sieve of Eratosthenes (primes ≤ n)
  • Powers and logarithms
  • Bit manipulation basics (AND, OR, XOR, shifts)

23 Core Patterns — Research shows these cover 90% of all coding interviews

Professor's Note: Stop solving random problems. Instead, learn to identify WHICH pattern a problem uses. Once you recognize "this is a sliding window" or "this is BFS on implicit graph," you already know 70% of the solution.

1 · Sliding Window

Use when array/string problem asks for contiguous subarray satisfying a condition. Window expands right and shrinks left.

▸ Longest Substring Without Repeat
▸ Min Window Substring
▸ Max Consecutive Ones III

2 · Two Pointers

Use on sorted arrays or linked lists. Left and right pointers move toward each other based on conditions.

▸ 3Sum, Container With Most Water
▸ Trapping Rain Water
▸ Remove Duplicates from Sorted Array

3 · Fast & Slow Pointers

Floyd's Cycle Detection. Fast moves 2x speed. Use for cycle detection, middle finding, palindrome checks.

▸ Linked List Cycle
▸ Happy Number
▸ Find the Duplicate Number

4 · Merge Intervals

Sort intervals by start time, then merge overlapping ones. Classic scheduling/calendar problem pattern.

▸ Merge Intervals
▸ Insert Interval
▸ Meeting Rooms II

5 · Cyclic Sort

When numbers are in range [1, n]. Place each number at its correct index. Find missing/duplicate in O(n), O(1) space.

▸ Find Missing Number
▸ Find All Duplicates
▸ First Missing Positive

6 · In-place Reversal of LinkedList

Reverse part of a linked list without extra space. Track prev, curr, next pointers carefully.

▸ Reverse Linked List II
▸ Rotate List
▸ Reverse Nodes in K-Group

7 · BFS (Tree/Graph)

Level-by-level traversal using a queue. Perfect for shortest path in unweighted graphs, level-order tree problems.

▸ Binary Tree Level Order
▸ Word Ladder
▸ Rotting Oranges

8 · DFS (Tree/Graph)

Go deep before backtracking. Use recursion (implicit stack) or explicit stack. For connected components, path problems.

▸ Number of Islands
▸ Clone Graph
▸ Path Sum

9 · Two Heaps

Maintain a max-heap of smaller half and min-heap of larger half. For median tracking, stream problems.

▸ Find Median from Data Stream
▸ Sliding Window Median
▸ IPO

10 · Subsets / Power Set

BFS approach: start with empty set, add each number to all existing subsets. Or bit masking for 2^n subsets.

▸ Subsets I/II
▸ String Permutations
▸ Balanced Parentheses

11 · Modified Binary Search

Binary search on "search space" not just sorted array. Key insight: shrink the space by half at each step.

▸ Rotated Sorted Array
▸ Search in Bitonic Array
▸ Ceiling of a Number

12 · Top K Elements

Use a min-heap of size K. Maintain it as you scan. O(n log k) which is better than O(n log n) sort.

▸ Top K Frequent Elements
▸ K Closest Points
▸ Kth Largest in Stream

13 · K-way Merge

Use min-heap to merge K sorted lists/arrays. Push (value, list_index, element_index) into heap.

▸ Merge K Sorted Lists
▸ Kth Smallest in M Sorted Arrays
▸ Smallest Range Covering K Lists

14 · 0/1 Knapsack DP

Each item: take or don't take. dp[i][w] = max value with i items and capacity w. Can optimize to 1D.

▸ 0/1 Knapsack
▸ Equal Subset Partition
▸ Target Sum

15 · Unbounded Knapsack

Items can be reused. dp[w] = max using unlimited supply. Different from 0/1: inner loop order matters.

▸ Unbounded Knapsack
▸ Coin Change
▸ Minimum Coin Change

16 · Fibonacci Numbers DP

Current value depends on previous values. Classic 1D DP. Space optimize: only keep last 2 values.

▸ Fibonacci, Climbing Stairs
▸ House Robber
▸ Jump Game

17 · Palindromic Subsequence DP

dp[i][j] = palindrome info for s[i..j]. Fill table diagonally for increasing lengths.

▸ LPS, Palindromic Substrings
▸ Min Deletion to Make Palindrome
▸ Palindrome Partitioning

18 · LCS Pattern DP

Compare two sequences. dp[i][j] = answer for first[0..i] and second[0..j]. Many string problems reduce to this.

▸ LCS, Edit Distance
▸ Longest Common Substring
▸ Shortest Common Supersequence

19 · Topological Sort

For DAGs: find valid ordering of nodes. Use in-degree count + BFS (Kahn's) or DFS post-order reverse.

▸ Course Schedule I/II
▸ Alien Dictionary
▸ Sequence Reconstruction

20 · Trie

Prefix tree for string operations. O(m) search where m = word length. For autocomplete, prefix matching.

▸ Implement Trie
▸ Word Search II
▸ Design Search Autocomplete

21 · Union-Find (DSU)

Track connected components. Union by rank + path compression gives near O(1) per operation.

▸ Number of Islands II
▸ Redundant Connection
▸ Accounts Merge

22 · Monotonic Stack

Stack that maintains increasing or decreasing order. Pop elements that violate order. For "next greater/smaller" class of problems.

▸ Daily Temperatures
▸ Largest Rectangle in Histogram
▸ Trapping Rain Water

23 · Backtracking Template

Try → Recurse → Undo. Prune early. The template is always: for each choice → make choice → recurse → undo choice.

▸ N-Queens, Sudoku
▸ Combination Sum
▸ Generate Parentheses

24-Week Master Schedule — 2-3 hours/day

Professor's Rule of 3: Every topic needs 3 passes — (1) Learn the concept, (2) Solve 3-5 guided problems, (3) Solve 3-5 unseen problems. Never move on after just reading.
WEEKS 1–2
Foundations: Language + Big-O + Math
Set up your environment. Pick Python or C++. Master time/space complexity analysis. Complete 20 basic warmup problems on HackerRank or LeetCode Easy.
WEEKS 3–4
Arrays, Strings, HashMap
Solve the Neetcode 150 arrays section. Aim for 3 problems/day. Journal every new pattern you see. Re-solve problems you got wrong without hints after 2 days.
WEEKS 5–6
Two Pointers, Sliding Window, Stack, Queue
These 4 patterns are deeply connected. Practice recognizing when to use each. Do 15+ problems. Time yourself — aim for under 20 min per medium problem.
WEEKS 7–8
Linked Lists + Binary Search
Draw pointer diagrams on paper for every linked list problem. For binary search, practice the "shrink search space" mindset on at least 3 non-standard problems.
WEEKS 9–10
Trees — DFS, BFS, BST
Master ALL traversal variants. Visualize every tree problem. The key insight: recursive DFS on a tree IS postorder processing. 20+ tree problems this fortnight.
WEEKS 11–12
Graphs + Backtracking + Heap
Draw graphs explicitly. Implement adjacency list from scratch. Backtracking: write the template 5 times from memory. By end of week 12, do your first mock interview.
WEEK 13
MID-POINT ASSESSMENT 🎯
Take 5 LeetCode Weekly Contests (virtual). Solve 2 Codeforces Div. 2 rounds. Target: solve at least A+B+C problems. Identify your 3 weakest topics and spend 3 days drilling them.
WEEKS 14–15
DP — 1D Patterns
Start with Climbing Stairs and work up to Word Break. Write the recurrence BEFORE coding. Test your memoized solution, then convert to tabulation, then optimize space.
WEEKS 16–17
DP — 2D and Knapsack
Edit Distance and LCS are foundational — do them 3 times each. Knapsack: understand the "include/exclude" decision tree intuitively before memorizing the formula.
WEEK 18
DP — Advanced (Intervals, State Machine)
Burst Balloons and Best Time to Buy Stock IV are the "boss fights" of DP. Take time to fully understand. Don't rush.
WEEKS 19–20
Advanced Graphs + Greedy
Implement Dijkstra and Kruskal from scratch without reference. Greedy: always ask "can I prove this locally optimal choice leads to globally optimal?" Then code it.
WEEKS 21–22
System Design + LLD + Bit Manipulation
Design LRU Cache, URL Shortener, Twitter. Practice talking through your design out loud. Bit manipulation: solve 10 problems. Learn XOR identity: a^a=0, a^0=a.
WEEKS 23–24
MOCK INTERVIEWS + REVISION BLITZ
Do 2 mock interviews per day (Pramp, Interviewing.io, or with a friend). Re-solve your "starred" hard problems. Behavioral prep: 10 STAR stories covering leadership, failure, conflict, impact. Apply to target MNCs now.

The Professor's Final Rules

Rule 1 — Consistency beats intensity. 2 hours every day for 6 months beats 14-hour marathon weekends. Your brain needs sleep to consolidate algorithms into long-term memory.
Rule 2 — Struggle first, look up second. Spend 25–30 minutes genuinely stuck before reading a hint. This is where the real learning happens. If you look up the solution after 5 minutes, you learned nothing.
Rule 3 — Re-solve, don't just re-read. After studying a solution, close everything and solve it again from scratch 48 hours later. This is active recall — the most effective learning technique in cognitive science.
Rule 4 — Communicate while coding. In an MNC interview, a correct silent solution can lose to an incorrect but well-communicated attempt. Practice talking through your thought process from day one.
Rule 5 — Target your company. Google loves hard DP + graph theory. Amazon focuses on practical coding + behavioral (Leadership Principles). Microsoft likes system design early. Meta tests graphs and dynamic programming heavily. Research your target and bias your practice accordingly.
